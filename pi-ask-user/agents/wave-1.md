# ExecPlan: Pi Ask User Question Extension

**Status:** Implemented  
**Date:** 2026-10-16  
**Reference:** `@juicesharp/rpiv-ask-user-question` v2.13.8  
**Target:** Pi Coding Agent Extension (TypeScript)

## 1. Purpose / Big Picture

Pi Coding Agent向けに、参考実装 `@juicesharp/rpiv-ask-user-question` と同等の機能を持つ、独立した `ask_user` 拡張機能を実装する。

AIがユーザーに選択式・自由記述式の質問を提示し、回答を構造化データとして受け取れるようにする。

参考実装の機能性とAIによる質問呼び出し品質をできるだけ維持しながら、次の改善を加える。

1. **プロンプト最適化：** ツール定義およびシステムプロンプトへの追加トークンを最小化する。
2. **無操作タイムアウト：** デフォルト600秒で自動終了し、AIが作業を継続できるようにする。
3. **操作検知による制限解除：** ユーザーがキーボード操作またはマウススクロールを行った時点で、カウントダウンを完全に解除する。
4. **残り時間の可視化：** 質問UIに残り時間をリアルタイム表示する。
5. **最小化・再表示：** `Ctrl+O` で質問UIを切り替え、過去の会話を閲覧しやすくする。
6. **会話履歴スクロール改善：** フルスクリーンモードでも、質問UIと履歴閲覧を両立する。
7. **設定ファイル統一：** `~/.pi/agent/<extension_name>.json` を使用する。

優先順位：

**機能の同等性 > 質問呼び出し品質 > 操作性・安定性 > トークン削減 > 実装の簡潔さ**

## 3. Functional Requirements

### FR-01. 質問機能

参考実装と同等の質問機能を提供する。

- 1回につき1〜4問
- 各質問につき2〜4選択肢
- 単一選択・複数選択
- 各選択肢の説明文
- 質問ごとの短いヘッダー
- 自由記述回答
- 複数行入力
- 複数選択と自由記述の併用
- Markdownプレビュー
- 質問ごとのメモ
- 質問票全体のメモ
- タブ切り替え
- Submitタブによる回答確認
- 部分回答での送信
- Escによるキャンセル
- 回答内容の構造化データ返却

参考実装のバリデーション、予約ラベル、入力正規化、回答形式も原則として踏襲する。

### FR-02. キーボード操作

参考実装の既存操作を維持する。

| 操作 | 動作 |
|---|---|
| ↑ / ↓ | 選択肢の移動 |
| Enter | 選択・確定 |
| Space | 複数選択 |
| Tab | 質問タブ切り替え |
| `n` | メモ入力 |
| Shift+Enter | 入力中の改行 |
| Ctrl+G | 外部エディタ |
| Ctrl+U | 入力クリア |
| Esc | 質問のキャンセル |
| **Ctrl+O** | **質問UIの最小化・再表示** |
| PageUp / PageDown | 会話履歴スクロール |

キーの処理はPi本体のイベントルーティングと競合しないようにする。

### FR-03. Ctrl+Oによる最小化・再表示

質問UI表示中に `Ctrl+O` を押すと、質問UIを最小化する。

最小化中に再度 `Ctrl+O` を押すと元の質問UIへ復帰する。

#### 最小化時の動作

- 質問UIを1行程度のコンパクトな表示に縮小する。
- 質問の待機状態は維持する。
- 選択済みの回答を維持する。
- 自由記述の入力途中データを維持する。
- メモの内容を維持する。
- 質問タブとフォーカス状態を可能な限り保持する。
- 会話履歴をスクロール可能にする。
- 元の画面に戻すための案内を表示する。

最小化時の表示例：

`? 質問待機中 | 制限解除済み | Ctrl+O: 再表示`

最小化は質問の確定やキャンセルを意味しない。

**Ctrl+O自体がユーザー操作に該当するため、最小化した時点でカウントダウンも解除される。**

#### キーバインドの競合対策

Pi本体では `Ctrl+O` がツール出力の展開・折りたたみに利用されている。

以下の方針とする。

1. 質問UIがアクティブな間だけ、本拡張のCtrl+O操作を優先する。
2. 質問UIが開いていない場合はPi本体のCtrl+O動作を変更しない。
3. 最小化中もCtrl+Oを検出できるようにする。
4. キーイベントがPi本体へ二重伝播しないようにする。
5. 既存のキーバインドとの優先順位を実際のPi SDKで確認する。

`ctx.ui.onTerminalInput()` などを利用して実現可能性を検証する。

利用可能な公開APIで安全に実装できることを優先する。

### FR-04. 質問タイムアウト

設定項目：

`timeoutSeconds`

| 設定値 | 動作 |
|---|---|
| 未設定 | 600秒 |
| `600` | 600秒 |
| `30` | 30秒 |
| `null` | 無期限 |
| `0` | 無期限 |
| 負の数値 | 無期限 |

正の有限数であれば小数も許可する。

無効な型や非有限数は検証し、デフォルト値へフォールバックする。

タイムアウトは1回の質問ツール呼び出し全体に適用する。複数質問のタブを移動してもタイマーは共有する。

#### タイマー開始

質問UIが表示され、ユーザーからの回答を受け付けられる状態になった時点で開始する。

モジュール読み込み時間やUI初期化時間はカウントに含めない。

無期限設定の場合、タイマーは生成しない。

### FR-05. カウントダウン表示

時間制限が有効な間は、質問UIのヘッダーまたはフッターに残り時間を表示する。

表示例：

`? 実装方針を選択してください | 残り 09:59`

表示仕様：

- 初期値は `10:00`。
- 原則1秒間隔で更新する。
- 残り時間は `MM:SS` または `HH:MM:SS` 形式とする。
- 秒数の減少が視覚的に確認できること。
- タイマーの期限はUIの描画周期に依存させない。
- 画面リサイズ時にも表示が壊れないこと。
- 残り時間が少なくなった場合は、必要に応じて視覚的に区別する。

カウントダウンはモデルの生成処理を必要としない。すべてローカルのTypeScript処理で完結させる。

無期限設定の場合は `時間制限なし` と表示する。

### FR-06. ユーザー操作によるカウントダウン解除

**質問待機中に、ユーザーによるキーボード操作またはマウススクロールを一度でも検出したら、タイムアウトを永久に解除する。**

解除後は、現在の質問票が終了するまで自動タイムアウトを再開しない。

600秒へのリセットや一時停止ではない。

対象とする操作：

- 通常のキー入力
- 矢印キー
- Tab
- PageUp / PageDown
- Ctrl+O
- その他のキーボードショートカット
- マウスホイールによるスクロール
- トラックパッドのスクロール（ターミナルがイベントとして通知できる場合）

クリックやマウス移動は今回の必須対象としない。

入力イベントの検出によって、質問UIや会話履歴の本来の操作を妨げてはならない。

例えば、マウスホイールで会話履歴をスクロールした場合は、カウントダウンを解除すると同時に、会話履歴も通常どおりスクロールする。

#### カウントダウン解除後

表示を以下のように変更する。

`? 実装方針を選択してください | 時間制限解除済み`

解除後はタイマーを破棄し、カウントダウンの描画更新も停止する。

質問UIを最小化・再表示しても、タイムアウトは再開しない。

#### 操作検知の対象範囲

Piの対話セッションに届いた実際のユーザー入力を対象とする。

次のイベントでは解除しない。

- モデルの出力
- ツールの実行ログ
- UIの再描画
- タイマーによる更新
- 端末サイズ変更だけのイベント
- プログラムによって生成された内部イベント

質問表示開始前の操作は対象外とする。

#### 検出上の注意

ターミナルの設定によっては、マウススクロールがPiへ直接通知されない場合がある。

この場合、受信した矢印キー等のイベントから操作を検出できるか確認する。

OSやターミナルが入力イベントをPiへ送信しない場合、その操作を確実に検出することはできない。

この制約をREADMEに記載し、主要な検証環境ではスクロールイベントを正常に検出できることを確認する。

### FR-07. タイムアウト時の動作

制限時間までユーザー操作がなかった場合は、次の処理を実行する。

1. タイムアウトを確定する。
2. 質問UIを終了する。
3. 確定済みの部分回答を保持する。
4. 未回答の質問を識別する。
5. タイムアウトを明示したツール結果を返す。
6. AIエージェントの処理を再開する。

結果には次の状態を区別できる情報を含める。

- 通常回答
- ユーザーによるキャンセル
- タイムアウト
- エラー

タイムアウト結果の追加フィールドとして `timedOut: true` を採用する。

ユーザーが回答していない選択肢を、自動的に選択済みとして扱わない。

モデルにはタイムアウトの事実を伝え、合理的で安全な仮定の下で作業を継続するよう案内する。

同じ質問を直ちに繰り返さないこと。

明示的な承認を必要とする危険な操作は、タイムアウトによって自動承認しない。

### FR-08. タイマーと操作の競合制御

次のイベントが同時期に発生しても、正しく処理できること。

- キーボード操作
- マウススクロール
- 通常回答の確定
- ユーザーキャンセル
- 外部回答
- タイムアウト
- エージェント中断

タイマーには単調増加時計を利用した締め切り管理を採用する。

単なるカウントダウン表示の更新回数で期限を判断しない。

期限前にユーザー操作が受理された場合は時間制限を解除する。

タイムアウトが先に確定している場合は、その後のユーザー操作によって結果を変更しない。

確定処理は一度だけ実行する。

終了時には、タイマー、入力リスナー、UIリソースを適切に解放する。

## 4. Fullscreen / Scrolling Requirements

### FR-09. 質問中の履歴スクロール

Piのフルスクリーンモードでも、質問UIを表示したまま会話履歴をスクロールできること。

- PageUp / PageDownに対応する。
- マウスホイールに対応する。
- スクロールによって質問の選択状態が変化しない。
- 質問UIが会話履歴を不必要に覆わない。
- 質問の入力途中データを保持する。
- 端末サイズに応じて表示領域を調整する。

PiのインラインUIを優先する。

複数質問の並列実行など、オーバーレイが必要になる場合でも、履歴を閲覧できる手段を確保する。

### FR-10. 最小化中の履歴閲覧

Ctrl+Oで質問UIを最小化した場合、会話履歴の閲覧を妨げないこと。

特に以下を確認する。

- フルスクリーンモード
- 通常のインライン表示
- オーバーレイ表示
- 他のオーバーレイが存在する場合
- 複数質問が同時に発生する場合

最小化中の入力イベントも、質問の再表示に必要なCtrl+Oを検出できるようにする。

スクロール操作はPi本体へ適切に渡す。

最小化中のユーザー操作も、質問待機中であればカウントダウン解除の対象とする。

## 5. Configuration Requirements

### FR-11. 設定ファイル

配置先：

`~/.pi/agent/<extension_name>.json`

`<extension_name>` は実装する拡張機能名に置き換える。

設定ファイルは任意であり、存在しなくても動作する。

#### 設定例

```json
{
  "timeoutSeconds": 600,
  "collapseKey": "ctrl+o",
  "guidance": {
    "promptGuidelines": []
  }
}
```

#### 設定項目

| 項目 | デフォルト |
|---|---|
| `timeoutSeconds` | `600` |
| `collapseKey` | `"ctrl+o"` |
| `guidance.description` | 最適化した説明文 |
| `guidance.promptSnippet` | 最適化した短文 |
| `guidance.promptGuidelines` | `[]` |

`collapseKey` は設定で変更可能とする。`"off"` による無効化もサポートする。

設定ファイルは自動作成しない。

不正なJSONは警告を出してデフォルト設定へフォールバックする。

質問タイムアウトの設定は、質問開始時に読み込む。同一質問の途中では変更しない。

## 6. Prompt Optimization

### FR-12. 追加トークンの削減

元実装の呼び出し品質を維持しながら、以下の情報を最小化する。

- `description`
- `promptSnippet`
- `promptGuidelines`
- JSONスキーマのフィールド説明

最適化方針：

1. ツールの使用条件だけを簡潔にモデルへ伝える。
2. JSONスキーマで制約できるものはスキーマに移す。
3. UIのキー操作や画面描画方法をモデルへ説明しない。
4. 質問票の構造や予約語はランタイムで検証する。
5. タイムアウトの具体的な動作はTypeScript側で制御する。
6. タイムアウト後の継続方針はツール結果に含める。
7. `promptGuidelines` は原則空配列とする。

必要に応じて、短いツール説明へ以下の判断基準を含める。

> Ask only when a decision is necessary and cannot be reasonably inferred. Batch related questions.

モデルが適切な場面で質問できることを優先する。

### FR-13. 質問品質の評価

元実装との比較評価を行う。

評価指標：

- 追加コンテキストトークン数
- 必要な質問の呼び出し率
- 不要な質問の呼び出し率
- 質問JSONの生成成功率
- 複数質問のまとめ方
- 選択肢説明の品質
- タイムアウト時の作業継続率

同じモデル・同じ入力・同じ設定で比較する。

## 7. Host Compatibility

### FR-14. TUI / RPC / ACP

参考実装と同様に、インタラクティブTUI、RPC、ACPに対応する。

TUIでは以下をすべて実装する。

- カウントダウン表示
- キーボード操作による制限解除
- スクロールによる制限解除
- Ctrl+Oによる最小化・再表示
- 会話履歴のスクロール

RPC/ACPではホストのネイティブダイアログを利用する。

ホストが操作イベントや表示更新を提供する場合は、カウントダウン表示および操作検知に利用する。

ホストが操作イベントを公開しない場合は、タイムアウトと回答処理を優先し、実現できないUI機能を明示する。

ネイティブダイアログのタイムアウトが実際に終了処理まで行われることを確認する。

Promiseの解決だけで画面を放置しない。

### FR-15. 非対話環境

非対話環境では `ask_user` をモデルのツール一覧から除外する。

`before_agent_start` でUIの有無を確認する。

UIを利用できないツールがモデルのコンテキストを消費しないようにする。

### FR-16. 外部回答イベント

参考実装と同等の外部回答機能を提供する。

- 質問開始イベント
- 待機開始・終了イベント
- 外部回答・キャンセル
- 結果通知
- `toolCallId` による識別
- 同時質問の処理
- 最初の有効回答のみ採用
- 不正な回答の拒否

外部回答で質問が確定した場合は、タイマーも終了させる。

タイムアウト後の外部回答は拒否する。

### 必須テストシナリオ

**Scenario A：完全無操作**

`timeoutSeconds: 5` に設定し、5秒間操作しない。

期待結果：質問UIが閉じ、タイムアウト結果がAIへ返る。

**Scenario B：キー入力による解除**

5秒の制限で開始し、3秒後に矢印キーを押す。

期待結果：時間制限が解除され、5秒経過後も質問が開いている。

**Scenario C：スクロールによる解除**

5秒の制限で開始し、3秒後に会話履歴をスクロールする。

期待結果：時間制限が解除され、会話履歴も正常にスクロールする。

**Scenario D：最小化による解除**

5秒の制限で開始し、3秒後にCtrl+Oを押す。

期待結果：質問UIが最小化され、タイムアウトが解除される。再度Ctrl+Oで元に戻せる。

**Scenario E：入力操作なし**

タイムアウトを解除せず、プログラム側でUIを再描画する。

期待結果：カウントダウンは継続する。

**Scenario F：競合条件**

期限直前に回答、外部回答、キー操作を発生させる。

期待結果：最初に成立した終了または解除の状態が一貫して処理される。

## 10. Risks / Mitigations

| リスク | 対策 |
|---|---|
| Ctrl+OがPi本体と競合 | 質問アクティブ中だけ優先処理する |
| 最小化すると再表示できない | Raw Inputを含む入力経路を検証する |
| マウススクロールが検出できない | ターミナル別にイベント経路を確認する |
| UI更新でタイマーがずれる | 単調増加時計に基づく締め切り判定 |
| 操作検知後もタイマーが残る | 明示的なタイマー破棄と状態遷移 |
| タイムアウト直前の競合 | 一度限りの確定処理と期限判定 |
| RPCでダイアログが残る | SDKの中断・タイムアウトAPIを確認 |
| プロンプト短縮で質問品質が下がる | 元実装とのモデル別比較テスト |
| オーバーレイがスクロールを妨げる | インライン優先、入力イベントを適切に委譲 |

## 13. Outcomes & Retrospective

実装した機能:

- `ask_user`。1〜4問、各2〜4選択肢、単一選択・複数選択、自由記述、プレビュー、メモ、タブ、部分回答、Esc キャンセル。
- デフォルト600秒の無操作タイムアウト、カウントダウン、初回のキーまたはマウスホイールで期限を解除。
- `Ctrl+O` で最小化・再表示。質問がないときは Pi 本体の `Ctrl+O` を変えない。
- 設定は `getAgentDir()/pi-ask-user.json`。既定では `~/.pi/agent/pi-ask-user.json` で、`PI_CODING_AGENT_DIR` も反映する。ファイルは自動作成しない。
- RPC/ACP はホストの select/input にタイムアウトを渡す。非対話時は `before_agent_start` でツールを外す。
- 外部回答は `rpiv:ask-user:*`。最初の確定だけを採用する。

参考実装との差分:

- 設定場所を `~/.pi/agent/pi-ask-user.json` に変更した。
- 最小化キーのデフォルトを `ctrl+]` から `ctrl+o` に変更した。
- 無操作タイムアウト、カウントダウン、操作による解除を追加した。
- `@juicesharp/rpiv-config` と `@juicesharp/rpiv-i18n` には依存しない。ロケール JSON は同梱する。
- ツール説明、スニペット、ガイドライン、スキーマ説明を短くした。ガイドラインのデフォルトは空配列。

検証:

- ユニットテストで設定、期限判定、操作判定、回答・キャンセル・タイムアウトの区別、プロンプト文字数を確認した。
- 参照実装の説明・スニペット・ガイドライン合計は 2944 文字。本パッケージはそれより短い。
- 質問判断品質のモデル比較、フルスクリーンでの実機操作、RPC ダイアログの実ホスト確認は、この作業環境では実行していない。

残る制約:

- ターミナルがホイールを Pi に送らない場合、その操作では期限を解除できない。PageUp / PageDown は送られれば解除され、履歴もスクロールする。
- RPC/ACP のネイティブダイアログは、ホストがキーやホイールを Pi に渡さない限り、操作による期限解除ができない。タイムアウトと回答処理は行う。
- オーバーレイ表示中にダイアログの上でホイールしたときは、Pi が履歴スクロールに渡す前にオーバーレイがイベントを受ける。最小化すると履歴を閲覧できる。
