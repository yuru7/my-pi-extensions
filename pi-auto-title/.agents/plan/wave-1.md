# ExecPlan: pi-auto-title

## 1. Purpose / Big Picture

Pi Coding Agentのターミナルタブタイトルを自動管理する拡張機能 `pi-auto-title` を実装する。

本拡張機能は次の2つの機能を提供する。

1. 会話内容をAIで要約し、短いタブタイトルを自動生成する。
2. エージェントの動作状態をタブタイトル先頭の文字で表示する。

ユーザーは複数のPiセッションを並列実行したときに、各タブの作業内容と動作状況を一目で識別できるようになる。

設定ファイルは任意とし、初回起動時にファイルを自動生成しない。設定が存在しない場合は内部デフォルト値で動作する。

`/auto-title init` コマンドでデフォルト設定ファイルを生成・初期化できる。

## 3. Configuration

### 3.1 設定ファイル

設定ファイルは以下に固定する。

    ~/.pi/agent/pi-auto-title.json

`~` はOSのホームディレクトリとして解決する。

設定ファイルが存在しない場合、ファイルを生成せず内部デフォルト設定を適用する。

設定ファイルが存在する場合は内容を読み込み、未指定項目にはデフォルト値を適用する。

設定ファイルの読み込みはセッション開始時に行う。変更を反映するにはPiの `/reload` を利用する。

### 3.2 デフォルト設定

```json
{
  "autoTitle": {
    "enabled": true,
    "model": "CURRENT",
    "thinkingLevel": "CURRENT",
    "fallbackToCurrentModel": true
  },
  "statusIndicator": {
    "enabled": true,
    "running": "⏳",
    "idle": "✅"
  }
}
```

### 3.3 autoTitle

| キー | 型 | 初期値 | 説明 |
|---|---|---|---|
| enabled | boolean | true | AIタイトル生成の有効・無効 |
| model | string | "CURRENT" | タイトル生成用モデル |
| thinkingLevel | string | "CURRENT" | タイトル生成時の思考量 |
| fallbackToCurrentModel | boolean | true | 指定モデルが利用できない場合のフォールバック |

`model` に設定できる値：

- `CURRENT`：タイトル生成時点のPiのアクティブモデル
- `provider/model-id`：明示的なモデル指定

モデル指定の例：

    openai/gpt-5.4
    anthropic/claude-sonnet-4-5

上記は書式例であり、実際に利用できるモデルはPiのモデルレジストリで確認する。

`thinkingLevel` に設定できる値：

- `CURRENT`
- `off`
- `minimal`
- `low`
- `medium`
- `high`
- `xhigh`
- その他、導入済みPiが対応する思考量

`CURRENT` は、タイトル生成を開始した時点でのアクティブなPiセッションの思考量を使用する。

明示的に指定した思考量が対象モデルで利用できない場合、Piの思考量の正規化規則に従ってサポートされる値へ調整する。調整した場合はログへ記録する。

通常セッション側のモデルや思考量を変更してはならない。

### 3.4 statusIndicator

| キー | 型 | 初期値 | 説明 |
|---|---|---|---|
| enabled | boolean | true | 動作状態表示の有効・無効 |
| running | string | "⏳" | 動作中の文字 |
| idle | string | "✅" | 完了・待機中の文字 |

`running` と `idle` はそれぞれ任意のUnicode文字列を指定可能とする。

空文字列も許可し、その状態では接頭辞を表示しない。

設定値はユーザー指定どおりに扱い、強制的な絵文字変換などは行わない。

## 4. Title Format

### 4.1 基本形式

動作状態表示が有効な場合：

    <status> Pi - <title>

動作状態表示が無効な場合：

    Pi - <title>

`<title>` は以下の優先順位で決定する。

1. AIで生成したタイトル
2. Pi起動時のディレクトリ名

### 4.2 起動ディレクトリ名

Pi起動時の作業ディレクトリから、末尾1階層の名称を取得する。

例：

    /home/user/projects/web-app
    → web-app

    /home/user/projects/web-form
    → web-form

    C:\Users\user\projects\api-server
    → api-server

初期化時に確定し、作業途中でディレクトリが変更されても更新しない。

Windows、WSL、Linuxのパスを考慮する。

パスのルートなど末尾名が得られない場合は `workspace` を代替名とする。

### 4.3 AIタイトルの最大文字数

AI生成タイトル部分は最大30文字とする。

`Pi - ` および動作状態文字は30文字制限に含めない。

文字数はJavaScriptのUTF-16コードユニット数ではなく、Unicodeのコードポイント数で判定する。

生成時のプロンプトで30文字以内を指示するとともに、生成結果に対してもコード側で長さ制限を適用する。

短く端的なタイトルを優先し、目安として10〜20文字程度を推奨する。

可能な限り単語や意味の区切りを保つ。30文字を超える場合は安全に切り詰める。

空文字列など有効でないタイトルが生成された場合は既存タイトルを維持する。

## 5. AI Title Generation

### 5.1 生成タイミング

AIタイトルはセッションの最初のユーザーメッセージを取得した時点で生成する。

起動直後は会話内容が存在しないため、ディレクトリ名を表示する。

最初のユーザーメッセージが入力されたら、その内容を基にAIタイトルを生成する。

初回生成が成功した場合、原則として同一セッション中は再生成しない。

通常のターンのたびにAIリクエストを実行しないことで、APIコストと不要な処理を抑える。

新規セッションに切り替わった場合は、そのセッションの内容に基づいてタイトルを生成する。

既存セッションを再開した場合、保存済みのAIタイトルがあれば復元し、不要な再生成を避ける。

タイトルはセッション単位で管理し、異なるセッション間で混同しないこと。

### 5.2 生成に利用する情報

原則として最初のユーザーメッセージのみを利用する。

ただし、短い初回メッセージだけでは作業内容を判断できないケースについては、実装時に必要最小限のコンテキスト利用を検討する。

大量の会話履歴、ツール実行結果、ファイル内容、システムプロンプトなどは無条件に送信しない。

AIに渡す入力は適切な上限を設ける。

送信対象のユーザー入力には個人情報や機密情報が含まれる可能性があるため、タイトル生成に使用するモデル・プロバイダーへ追加リクエストが送信されることをREADMEに明記する。

### 5.3 生成プロンプト

タイトル生成には専用の短いプロンプトを使用する。

要求事項：

- ユーザーの作業内容を表すタイトルを生成する。
- 日本語の入力には原則として日本語で応答する。
- 30文字以内とする。
- 可能な限り短く端的にする。
- 単なる話題よりも作業目的を優先する。
- タイトルのみを出力する。
- 引用符、説明文、Markdownを出力しない。
- 先頭に `Pi - ` や状態アイコンを含めない。
- 元の入力にない情報を推測で補わない。

例：

    入力：
    AWS Lambdaでフォーム公開APIを実装したい

    出力：
    Lambdaフォーム公開API

    入力：
    CircleCIのDynamic Configurationへの
    移行内容をレビューして

    出力：
    CircleCI設定移行レビュー

### 5.4 モデル呼び出し

Piが提供するAIライブラリを使用し、メインエージェントとは独立した軽量な推論リクエストを実行する。

原則として `@mariozechner/pi-ai` の `complete` / `completeSimple` などを調査して採用する。

AI呼び出しには次の条件を満たす実装を選ぶ。

1. 任意のモデルを明示的に指定できる。
2. 対応する認証情報をPi経由で取得できる。
3. 思考量を個別に指定できる。
4. メインセッションのモデル設定に影響しない。
5. 非同期実行できる。
6. エラーとタイムアウトを処理できる。

Pi側の `setModel()` や `setThinkingLevel()` を一時的に変更してタイトルを生成する方式は採用しない。

AI生成リクエストをPi本体の会話履歴へ追加しない。

### 5.5 非同期実行

タイトル生成が完了するまでメインエージェントを待たせない。

タイトル生成中も通常のエージェント処理を進行させる。

生成完了時にタブタイトルの `<title>` 部分のみ更新する。

現在の動作状態アイコンを変更してはならない。

例：

    ⏳ Pi - web-app
              ↓ AI生成完了
    ⏳ Pi - フォーム公開API改善
              ↓ エージェント処理完了
    ✅ Pi - フォーム公開API改善

非同期処理の競合を防止するため、生成リクエストごとに識別子を保持する。

セッション切り替え後に古い生成結果が返ってきた場合、その結果で現在のタブタイトルを上書きしてはならない。

キャンセル可能なAPIであれば、不要になった生成処理を中断する。

## 6. Model Resolution & Fallback

### 6.1 モデル選択

`model = "CURRENT"` の場合、現在のPiセッションのアクティブモデルを使用する。

それ以外の場合、指定された `provider/model-id` をモデルレジストリから検索する。

モデルが見つかり、認証情報を利用できる場合は指定モデルを使用する。

### 6.2 フォールバック条件

以下の場合をフォールバック対象とする。

- 指定モデルがレジストリに存在しない。
- 指定モデルの認証情報を取得できない。
- 指定モデルの呼び出しに失敗した。

`fallbackToCurrentModel = true` の場合、現在アクティブなモデルへの切り替えを試みる。

フォールバック先が当初のモデルと同じ場合は再試行しない。

フォールバックは最大1回とし、無限に再試行しない。

フォールバック時も、設定された思考量を可能な範囲で適用する。

`thinkingLevel = "CURRENT"` の場合は現在の思考量を使用する。

### 6.3 フォールバック通知

指定モデルから現在モデルへのフォールバックが発生した場合、Pi画面上に注意メッセージを表示する。

`ctx.ui.notify(..., "warning")` を使用する。

通知例：

    pi-auto-title:
    指定モデルを利用できないため、
    現在のモデルにフォールバックしました。

可能な限り以下の情報を含める。

- 指定モデル
- フォールバック先モデル
- フォールバック理由

機密情報や認証トークンは表示しない。

通常動作時には通知しない。

### 6.4 フォールバック無効時

`fallbackToCurrentModel = false` で指定モデルが利用できない場合は、AIタイトル生成を中止する。

表示済みのタイトルを維持する。

AIタイトルが未生成なら起動ディレクトリ名を継続表示する。

原因は警告ログへ記録する。

### 6.5 全モデル失敗時

フォールバック先も利用できない場合はAIタイトル生成を諦める。

タブタイトルにはディレクトリ名を残し、Pi本体のエージェント処理は正常に継続させる。

タイトル生成の失敗をメインエージェントの失敗として扱わない。

## 7. Status Indicator

### 7.1 状態管理

以下の2状態を管理する。

    running
    idle

初期状態は `idle` とする。

### 7.2 動作開始

`agent_start` で `running` に変更する。

    ⏳ Pi - <title>

推論、ツール呼び出し、自動継続など、エージェント処理中は動作状態を維持する。

### 7.3 動作完了

`agent_settled` を基本イベントとして、処理完了時に `idle` へ変更する。

    ✅ Pi - <title>

実装対象バージョンのPiにおいて `agent_settled` の発火条件を確認する。

中断・エラー・自動継続・追加のキューメッセージについて検証し、必要であれば追加イベントや `ctx.isIdle()` などを利用して正しい状態を反映する。

`agent_end` だけで完了を判定しない。

### 7.4 状態表示が無効な場合

`statusIndicator.enabled = false` の場合、アイコンを完全に省略する。

    Pi - <title>

内部的な状態管理は継続してもよいが、状態変化だけを理由とした同一タイトルの再設定は行わない。

### 7.5 タイトル更新の最適化

現在表示しているタイトルを保持する。

新しいタイトルと一致する場合は `ctx.ui.setTitle()` を呼び出さない。

タイトルの生成処理と状態変更処理は分離し、表示文字列の組み立ては共通関数へ集約する。

## 8. /auto-title init

### 8.1 コマンド

以下のスラッシュコマンドを登録する。

    /auto-title init

`pi.registerCommand("auto-title", ...)` を利用する。

### 8.2 ファイルがない場合

デフォルト設定を以下へ出力する。

    ~/.pi/agent/pi-auto-title.json

必要な親ディレクトリが存在しない場合は作成する。

JSONはインデント2スペースで整形し、末尾に改行を付ける。

作成後、画面に成功通知を表示する。

### 8.3 ファイルがある場合

既存の設定ファイルがある場合、デフォルト設定へのリセットとして扱う。

実行前に確認ダイアログを表示する。

    既存のpi-auto-title.jsonを
    デフォルト設定で上書きしますか？

キャンセル時は一切変更しない。

確認後、デフォルト設定で上書きする。

### 8.4 設定反映

`/auto-title init` 実行後は、新しいデフォルト設定を実行中の拡張機能にも反映する。

Pi全体の再起動は必要としない。

現在のセッションタイトルについては、更新後の設定に従って再描画する。

すでに生成済みのAIタイトルは維持する。

### 8.5 その他の引数

`/auto-title` の引数なし実行、または未対応の引数については、利用可能なコマンドと使い方を表示する。

今回実装するサブコマンドは `init` のみとする。

## 9. Session Lifecycle

### 9.1 起動時

1. 設定ファイルを読み込む。
2. 不足項目にデフォルト値を適用する。
3. 起動ディレクトリ名を取得する。
4. セッションに保存されたAIタイトルを確認する。
5. 状態を確認する。
6. タブタイトルを設定する。

### 9.2 新規セッション

新しいセッションでは、初期タイトルを起動ディレクトリ名とする。

そのセッションの最初のユーザー入力を受けてAIタイトルを生成する。

### 9.3 既存セッション再開

保存済みのAIタイトルがある場合はそれを復元する。

AIタイトルが保存されていない場合、既存セッションの最初のユーザーメッセージを利用した生成を検討する。

履歴取得とタイトル復元が可能か、PiのセッションAPIを調査する。

### 9.4 タイトルの永続化

AIタイトルはセッションに紐付けて保存する。

Piが提供する `pi.appendEntry()` などのセッション永続化APIの利用を優先する。

タイトル復元のためだけに別のグローバル管理ファイルを作成しない。

セッション切り替え時は、該当セッションのタイトルのみ表示する。

### 9.5 拡張機能のリロード

`/reload` で設定を再読み込みする。

リロード後も保存済みタイトルを利用できるようにする。

未完了の生成処理が存在する場合は、古い処理の結果を破棄する。

## 10. Error Handling

### 10.1 設定エラー

設定ファイルが存在しない場合は正常扱いとする。

JSON構文が不正な場合は、画面に警告を表示し、内部デフォルト設定を使用する。

型が不正な設定値は検証エラーとして扱い、対象フィールドの情報を警告へ含める。

不正な設定ファイルを自動修復・上書きしない。

### 10.2 AI生成エラー

AI生成処理の失敗は拡張機能内で処理する。

失敗理由を適切に記録する。

メインエージェントの処理には影響させない。

### 10.3 タイムアウト

AIタイトル生成が長時間応答しない場合に備え、適切なタイムアウトを設ける。

初期実装では30秒を目安とし、利用するAPIのキャンセル機構を優先する。

タイムアウトしても既存タイトルを維持する。

### 10.4 出力の検証

AI出力から前後の空白、不要な引用符、改行、Markdown装飾などを除去する。

制御文字などターミナルタイトルに不適切な文字を除去する。

結果が空文字列になる場合は採用しない。

30文字の長さ制限を適用する。

## 11. Architecture

拡張機能はTypeScriptで実装する。

推奨構成：

    pi-auto-title/
      index.ts
      config.ts
      title.ts
      generator.ts
      model.ts
      session.ts
      tests/
        config.test.ts
        title.test.ts
        generator.test.ts
        model.test.ts
        integration.test.ts
      README.md

責務：

- index.ts：拡張機能登録、イベント購読、コマンド登録
- config.ts：設定の読み込み、検証、初期化
- title.ts：文字列生成、状態表示、30文字制限
- generator.ts：AIタイトル生成と出力正規化
- model.ts：モデル選択、思考量、フォールバック
- session.ts：セッション別タイトル管理と永続化

必要以上の抽象化を避ける。

小規模な処理は統合してもよいが、AI生成、設定管理、タイトル更新はテスト可能な形で分離する。

## 12. Testing

### 12.1 設定ファイル

- 設定なしでデフォルト動作する。
- 初回実行で設定ファイルが生成されない。
- 未指定の設定項目にデフォルト値が適用される。
- 明示的なfalseが保持される。
- JSON不正時にデフォルトへフォールバックする。
- `/auto-title init` でファイルが作成される。
- `/auto-title init` でリセット確認が表示される。
- キャンセル時は既存ファイルが維持される。

### 12.2 タイトル生成

- 日本語のタイトルが生成される。
- 30文字以内に制限される。
- 不要な引用符が除去される。
- 改行や制御文字が除去される。
- AIタイトルが存在しない場合はディレクトリ名になる。
- AI無効時はAIリクエストが発生しない。
- 同一セッションで不要な再生成が発生しない。

### 12.3 モデルとフォールバック

- `CURRENT` で現在モデルが選択される。
- 明示的なモデル指定が反映される。
- `thinkingLevel = CURRENT` が正しく解決される。
- 明示的な思考量指定が反映される。
- 指定モデルが存在しない場合にフォールバックする。
- 認証情報がない場合にフォールバックする。
- フォールバック時に警告が表示される。
- フォールバック無効時は現在モデルを使用しない。
- フォールバックは最大1回で終了する。
- AI生成用モデルの選択がPi本体のモデルを変更しない。

### 12.4 動作状態

- 初期状態でidleアイコンが表示される。
- 処理開始時にrunningアイコンへ切り替わる。
- 処理完了時にidleアイコンへ戻る。
- 自動継続中に誤ってidleへ戻らない。
- 中断後にrunning状態が残らない。
- 状態表示無効時はアイコンが出ない。
- カスタムアイコンが反映される。
- 同じタイトルへの重複更新を行わない。

### 12.5 非同期処理

- AIタイトル生成中もエージェントが動作する。
- AI生成完了時に状態アイコンが維持される。
- 古いセッションの生成結果が新しいセッションを上書きしない。
- セッション切り替え後の非同期結果を適切に破棄する。
- エラーやタイムアウトでメイン処理が停止しない。

### 12.6 実機検証

Windows Terminal + WSL環境で確認する。

## 14. Acceptance Criteria

以下をすべて満たすこと。

1. 設定ファイルがなくても動作する。
2. 初回起動時に設定ファイルを作らない。
3. `/auto-title init` でデフォルト設定を生成・リセットできる。
4. AIが会話内容から30文字以内のタイトルを生成する。
5. AI生成タイトルは簡潔で、作業内容を識別できる。
6. 生成モデルと思考量を個別に設定できる。
7. モデルと思考量に `CURRENT` を使用できる。
8. モデルが使えない場合は設定に応じてフォールバックする。
9. フォールバック時に画面へ警告を表示する。
10. モデル呼び出しがPi本体のモデル設定に影響しない。
11. 動作中と待機中のアイコンが正しく切り替わる。
12. 状態表示の有効・無効と表示文字を設定できる。
13. AI生成に失敗してもディレクトリ名が表示される。
14. セッション再開時に生成済みタイトルを復元できる。
15. 複数のPiセッションで状態が混ざらない。
16. AIタイトル生成が通常のエージェント処理を妨げない。
17. テストが成功し、READMEが整備されている。

## 16. Decision Log

- 拡張機能名は `pi-auto-title` とする。
- 設定ファイルは `~/.pi/agent/pi-auto-title.json` に固定する。
- 設定ファイルがない場合はデフォルト値で動作する。
- デフォルトではAI生成と状態表示の両方を有効にする。
- AIモデルと思考量の初期値は `CURRENT` とする。
- AIタイトルはセッション単位で生成する。
- 生成タイミングは最初のユーザー入力を基本とする。
- AIタイトル生成は非同期で実行する。
- AIタイトル生成に失敗したら起動ディレクトリ名を使用する。
- フォールバック時は画面に警告を表示する。
- 状態表示は `⏳` / `✅` を初期値とする。
- 生成タイトルは最大30 Unicodeコードポイントとする。

## 17. Outcomes & Retrospective

- 使用したPiのバージョン
  - `@earendil-works/pi-coding-agent` 1.1.0 / `@earendil-works/pi-ai` 1.1.0 (Node v26.10.0)
- 採用したAPIとその選択理由
  - `ctx.ui.setTitle()`：タブタイトル設定の公式API。
  - `ctx.modelRegistry.streamSimple(model, context, { reasoning, signal, timeoutMs }).result()`：認証情報をPi経由で解決しながら、モデル・思考量を個別指定した独立リクエストを実行できるため。`pi-ai` の `completeSimple` は環境変数認証に依存するため不採用。
  - `clampThinkingLevel()` (pi-ai)：Pi本体と同じ思考量の正規化規則をそのまま利用するため。
  - `pi.appendEntry()` / `ctx.sessionManager.getBranch()` / `getSessionId()`：セッション内のタイトル永続化・復元・競合検知に利用。専用のグローバル管理ファイルは作らない。
  - イベント：`session_start` / `before_agent_start` / `agent_start` / `agent_settled` / `session_tree` / `session_shutdown`、コマンドは `pi.registerCommand("auto-title", ...)`。
  - 生成処理は呼び出し元の `AbortController` でキャンセル可能。`session_shutdown` / `session_tree` / セッション再初期化時に中断し、クライアントがsignalを無視してもPromiseが終了する。キャンセル・期限切れ直前に解決した応答も採用せず、永続化直前にも中断状態を確認する。キャンセル後はフォールバックしない。期限30秒は生成全体（認証解決とフォールバックを含む）に適用し、期限切れ後に次の試行は行わない。
  - フォールバック警告は「モデル未登録」「認証情報なし」「タイムアウト」「呼び出し失敗」の安全な理由分類だけを表示し、プロバイダーの生エラーは表示しない（詳細はログへ記録）。
  - `agent_settled` は「自動継続しない最終境界」としてドキュメントに明記されており、中断 (`aborted`) でも発火するため動作状態の完了判定に採用。`agent_end` は判定に使用しない。
  - 生成タイミングは実行される最初のユーザープロンプト (`before_agent_start`) とし、履歴にユーザーメッセージがある場合は `getBranch()` の最初のユーザーメッセージを優先。

### 追加対応(タブタイトルのライフサイクル)

- Pi起動直後のタイトル: 状態アイコンなしの `Pi - <title>` を表示し、初回の `agent_start` 以降は動作状態アイコン付き(`<status> Pi - <title>`)へ切り替える。
- Pi本体のタイトル上書き対策: `interactive-mode.js` の `updateTerminalTitle()` が拡張機能のバインド直後に `π - <dir>` を設定して上書きする経路を確認(`rebindCurrentSession` 内、`bindCurrentSessionExtensions()` の後に同期実装の `updateAvailableProviderCount()` を挟むだけ)。`session_start`・`session_info_changed`・`session_tree` のあとに遅延再適用(0ms/250ms/1000ms、`TitleDisplay.show(..., force)` で再送)し、連続発火時は前の予約を取り消して1バッチにまとめる。遅れて上書きされた場合に備えて `input` でも再適用する。確実性の範囲: ベストエフォート(即時設定 + 有限回の再適用 + 次回入力での修復)。他の拡張ハンドラーや `extendResourcesFromExtensions()` は非同期であり、タイマーが Pi の書き込みより後になる保証は無い。Pi の書き込みを知らせる公開フックも存在しないため、確実な維持は公開APIでは実現できない。
- Pi終了時のクリア: `session_shutdown` の `reason: "quit"` のときだけタイトルを空文字列に設定する(reload / new / resume / fork では行わない)。元タイトルは読み取れないため復元ではなく、ターミナル依存のクリア操作(デフォルト表示に戻るか空欄になる)。クリア後に届く生成結果や遅延再適用で再設定されないことをテストで確認。強制終了では何も実行されない。
